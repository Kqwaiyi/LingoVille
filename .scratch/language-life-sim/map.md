# Map: Language-learning life sim

Labels: wayfinder:map
Status: open

## Destination

A **game design doc + technical spec** for a single-player, low-poly 3D, desktop-browser life sim in which the player keeps a Character alive and happy by Speaking the Target Language to NPCs — detailed enough to slice straight into build tickets. Not the build itself.

## Notes

**Domain & glossary.** Use the terms in `CONTEXT.md` (Character, Well-being, Mood, Life Skill, Language Proficiency, Target Language, Native Language, Job, Fainting, Speaking, Typed Fallback, Help). Grilling tickets: call the Skill tool for `grilling` and `domain-modeling`; update `CONTEXT.md` as terms resolve. Research tickets: `research` skill, findings in `.scratch/language-life-sim/research/`. Prototype tickets: `prototype` skill.

**Who & constraints.** Solo dev building with AI agents; understands web-dev workflow and reviews agent output. Hackathon, ~2 months, but time is explicitly not a constraint on design ambition. Runs **locally only** — never publicly deployed — using the dev's own **Google Gemini** API key.

**Settled while charting (the starting frame — not tickets):**
- Presentation: **low-poly 3D**, free-roaming town, Bloxburg-like. **Single-player. Desktop browser only.**
- Conversation: **Speaking (voice) is primary**, with Help (hints, phrasebook, hear-it-said) and a Typed Fallback. NPCs reply with **TTS + a line in the chat column** (see HUD and conversation UI); reading aids (e.g. pinyin) for languages that need them. Tap-to-translate.
- Languages: **Japanese, Chinese, English, German** — each can be Native or Target; Target ≠ Native. UI localized to Native Language, defaulted from the player's region.
- Learners: all levels. Player picks a starting level; Language Proficiency then adjusts silently and NPCs adapt to it.
- Conversations: **goal-driven interactions are the backbone** (order coffee, pay a bill), succeed when **intent is understood**; free small talk allowed and lifts Mood. Corrections shown in a **post-conversation recap**, never mid-conversation.
- Systems: Life Skills and Language Proficiency are **separate** systems. **Jobs: yes.** Well-being out → **Fainting** (hospital, lost time, bill). Mood is one meter: up from successful talk/socializing/comfort, down from failures/unmet needs/overwork; low Mood cuts pay and Skill gain.
- Time: compressed day cycle (~24 real min/day) with opening hours.
- Home: **fixed, no customization**.
- Town: about a dozen places — home, café, supermarket, restaurant, hospital, park, transit — with 2–3 Jobs.
- Saves: browser storage, no accounts.

## Decisions so far

<!-- one line per closed ticket -->

- [Gemini voice capabilities for Japanese, Chinese, English, German](issues/03-gemini-voice-capabilities.md) — `gemini-3.8-live` does speech-in → reasoning → speech-out in one session for all four languages, with transcripts both ways and function calling (for "goal achieved"). It has no structured output and no pronunciation score, so a post-conversation `generateContent` call handles the recap. Recommended: a small local Node server that creates short-lived tokens. About $0.012 per conversation minute; latency to be measured in the prototype.
- [Reading aids for Chinese and Japanese](issues/05-reading-aids.md) — Hybrid: Gemini returns `{base, reading}` segments with each line (structured output). For Chinese, fall back to `pinyin-pro` when a reply fails validation; for Japanese, `wanakana` makes romaji and `kuroshiro` loads only on demand (its dictionary is ~18 MB). Text bubbles are DOM `<ruby>` elements placed over the 3D scene (e.g. CSS2DRenderer), and players can hide reading aids.
- [Web 3D stack for a low-poly life sim](issues/04-web-3d-stack.md) — React Three Fiber + drei on Three.js r186, with @react-three/rapier and Rapier's kinematic character controller; Babylon.js is the fallback. Performance doesn't decide it at this town size. Pin agents to the Three.js version, because r186 changed the shadow APIs. Assets: Kenney and Quaternius (CC0); one Quaternius character rig + animation library for the Character and all NPCs.
- [Core loop and economy](issues/01-core-loop-and-economy.md) — An open-ended sandbox with no win state or promotions. Money comes only from Jobs, with Shift pay set by interaction success, Mood and Life Skills. Costs are food and drink, weekly rent, comfort purchases, doctor and medicine, and hospital bills; transit is free. Random Illness has to be explained to a doctor. Rent starts with a Newcomer Discount that fades as Language Proficiency rises, and unpaid rent and hospital bills become debt rather than eviction. Pacing and budget ratios are in the ticket.
- [Anatomy of an interaction](issues/02-anatomy-of-an-interaction.md) — The player presses E and the NPC greets first; talking is hold-Space push-to-talk (open mic optional). Each Goal Interaction is data with one goal and typed facts, and the outcome follows what the NPC understood, which it reads back before calling the completion function. A hidden Patience count, lowered by `not_understood()`, decides failure; slowness never costs. Shift customers reverse the roles: the player fills a hidden order, checked exactly against data. The clock runs at ¼ speed during conversations, and a Shift is 5–8 customers. Small Talk can't fail and its Mood gain is capped per NPC per day. Every Recap is skippable, gives up to 3 corrections, and is saved to the Journal.
- [Voice conversation prototype](issues/06-voice-conversation-prototype.md) — **Keep** single-session `gemini-3.8-live`. Latency is about 0.9 s median, `serve_order` is reliable after the read-back, and an ephemeral token on v1beta works. Clarifying re-asks are free, so only turns the NPC can't make sense of at all cost Patience. The build must end a Goal Interaction after success and use Gemini TTS for hear-it-said, and learner transcripts are noisy.
- [Town and content scope](issues/07-town-and-content-scope.md) — One shared town layout with a **Culture Pack** for each Target Language (English uses a UK setting). There are 11 places with realistic hours. The three Jobs (barista, cashier, server) are all open from day 1, with 7 Shift customer templates. The launch catalogue is 25 player-led Goal Interactions tagged B/I/A. There are 4 Illnesses, each cured by its own medicine, and 5 Comfort Purchases. Prices are authored as Shift ratios: one Shift is ¥6,000 / 240元 / €60 / £60, the starting balance is about 1.7 Shifts, cooking at home is cheap, and tap water is free.
- [Life Skills and Language Proficiency models](issues/08-life-skills-and-proficiency.md) — Proficiency is a hidden score in six CEFR **Proficiency Steps** (B = A1–A2, I = B1–B2, A = C1–C2), moved by the Recap's level evidence, not XP. It can drift down, but the economy steps ratchet. The ticket has tables by step for Patience (4/4/3/3/2/2), the Newcomer Discount and Shift stakes, and sets the Shift customer mix. Life Skills are Cooking, Fitness, Barista, Cashier and Server, levels 0–5, shown to the player. Job skills earn a pay raise and help with the mechanics only. Gym membership is about 0.5 Shift a month.
- [Onboarding and Native Language selection](issues/09-onboarding-and-native-language.md) — Four setup screens: Native Language (from `navigator.languages`, falling back to English, changeable later), Target Language, self-assessment and a skippable mic check. A denied mic switches to the Typed Fallback. A skippable **First Morning** in the real town ends in a real café order where Patience can't run out. Each Job starts with a one-time hiring Goal Interaction, which adds 3 to the catalogue; after that, pressing E at the staff door starts a Shift.
- [Technical architecture](issues/10-technical-architecture.md) — Vite + React + strict TS with R3F and Zustand. A pure `sim` core keeps state; saves go to IndexedDB with Zod and migrations. A Node "Gemini gateway" holds the key and serves token/recap/tts/annotate, with a mock mode; the browser opens only the Live socket, through a `VoiceSession` class. NPC prompts are English meta-prompts built from blocks. Reading aids come from a library first and Gemini replaces them. Content is Zod-typed TS. The UI uses react-i18next. The repo layout has enforced import boundaries; tests are Vitest plus Playwright in mock mode. A network drop never penalises the player (a Shift customer is replaced).
- [NPC identity and memory](issues/11-npc-identity-and-memory.md) — About 15 **Named NPCs** (staff, park regulars, landlord), each with one persona localised per Culture Pack. Shift Customers are anonymous. Hidden **Familiarity** has three tiers (stranger/acquaintance/friend) and never fades. It rises through Small Talk, gifts and orders, under the shared daily cap. Friends give +1 Patience, more Mood from Small Talk and a one-time register switch (Sie→du, keigo→タメ口), with no discounts. Small Talk works with any idle Named NPC. Setup gains a name field, and NPCs learn the name through `learn_name`. Gifts count once a week, and each NPC has a favourite you find out by talking. A typed **NPC Memory** record per NPC reaches the prompt as a "You and this person" block.
- [Help economics](issues/12-help-economics.md) — Help is free (no money or Mood cost) and the same at every Proficiency Step. A per-conversation **Help log** makes the Recap evaluation discount helped turns (a repeated hint counts for little, a translated NPC line for nothing as evidence). Help only reduces weight and never lowers the estimate. In a Shift, a translated customer pays minus half the failure dock and gives no evidence. The only display is a positive "No Help needed" mark on the Recap and Journal entry.
- [Save model](issues/13-save-model.md) — 4 free slots (any Target Language) with Continue + a slot list. Autosave only, with no manual save. Conversations are never saved in progress, Shifts save after each customer, and the RNG state is saved so a reload can't dodge an Illness. Device settings (Native Language, input, tooltips seen) sit outside saves. The save is a small object that refers to content by id, and the Journal is a separate append-only store. Pre-migration and start-of-day backups mean nothing is deleted automatically. Saves export/import as JSON into an empty slot, delete needs the Character's name typed, there's no reset, and the game requests `storage.persist()`.
- [AI quality evaluation](issues/14-ai-quality-evaluation.md) — `npm run eval` in a new `evals/` folder, required before merging changes to `src/ai/` or `server/config.ts`, with no schedule. It runs mostly typed noisy-transcript turns plus a few of the dev's own recordings (gitignored), in all four languages. Deterministic checks are hard bars (stays in the Target Language, read-back before completion, Help never lowers the estimate, exact annotation `base`). A `gemini-3.8-pro` judge scores the rate bars, and a human spot-checks it. A drop of more than 5 points against the baseline fails, and only a human may update the baseline. The ticket also has the four annotate validation rules and a cost cap of about $1 a run / $15 in total.
- [HUD and conversation UI](issues/15-hud-and-conversation-ui.md) — In the world, a bottom dock is always visible: ring gauges for Well-being and Mood, the clock and money, with Saved ✓ in the dock. The First Morning prompt is a banner at the top. A conversation is a **chat column on the right**, with Chat and Help tabs, Translate and Replay on every line, and the mic button plus the typed field at the bottom. NPC text no longer floats over the scene. The Recap replaces the chat in that column as a Journal page with a "No Help needed" sticker. The title screen is a menu on the left over the live 3D scene, with the Character in the right third and a centre panel that follows the highlighted item. The prototype is on branch `prototype/hud-and-conversation-ui`.
