# e2e

Playwright smoke tests: the top seam, testing what the Player sees.

**Rules**
- Always run against the gateway in mock mode. `playwright.config.ts` starts `npm run dev` with `GEMINI_MOCK=1` on its own ports, and `GEMINI_MOCK_REPLY_MS=50` so the fake NPC answers in 50ms instead of 600. It still answers later, never within the same call, so tests wait for its lines as they would for a real NPC's.
- No automated 3D visual tests. Use roles and visible text, not scene internals.
- Specs take `test` and `expect` from `./test.ts`, which fails a test on any uncaught error in the page (lint enforces it).
- Start a game with `startNewGame` (`title.ts`). By default it loads the page with the dev-only `?newGame=<target>` shortcut, which lands straight in the First Morning as Sam, an English speaker at A1 in the first Appearance Preset, with the mic check skipped. It combines with `?at=`, `?day=`, `?spawn=`, `?faint` and `?ill`, and comes off the URL once read, so a reload shows the title screen. Answers it can't carry (another Native Language, level, name or Appearance Preset, or `skipTutorial`) go through the real screens. So does `throughScreens: true`: pass it in tests about the title screen, setup, the mic check, Continue or save slots, so those screens stay covered end to end.
- The first session's smoke (`smoke.spec.ts`) goes from setup through the First Morning's café order (typed, with no mic), its Recap and the Journal to Continue. Don't walk that path again elsewhere: a test about one step of it covers only what the smoke doesn't check. A new game is in the First Morning, whose café order can't fail, so a test that needs an order to fail passes `skipTutorial` (`talkToTheBarista(page, { skipTutorial: true })`).
- Wait on something the Player sees before each action, never on a fixed sleep or a timed key hold, so a test passes the same way on a fast or busy machine. Walk with `walkUntil` (`walk.ts`): it holds keys until a prompt shows, lets go in that frame, and walks on if the prompt flickers away. A helper that presses a key to open something waits for it to show before returning. Keep a `waitForTimeout` only where real time is what's measured (the clock, or how far a walk gets where nothing can show the Character stopped), with a comment naming it.

**Testing**: `npm run test:e2e` runs two tests at a time (2 workers; `playwright.config.ts` says why not more). To check that a race is gone, run the suite with `--repeat-each=3`. While iterating, run one file: `npx playwright test e2e/<name>.spec.ts`. Tracing is off by default. To debug a failing test, re-run it with a trace (`npx playwright test e2e/<name>.spec.ts -g "<test title>" --trace=on`), then open it with the `npx playwright show-trace …` command the failure prints.
